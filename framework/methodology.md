# Methodology

Venture OS optimizes for **decision quality per unit of time and money**, not for the number of artifacts produced.

## Core loop

```text
CONCEPT
  ↓
RESEARCH
  ↓
CHALLENGE
  ↓
DECIDE ───── PARK
  │
  ├──── TEST → EXPERIMENT → LEARN → DECIDE
  │
  └──── PROCEED → POSITION → EXPERIMENT → LEARN → DECIDE
```

The loop is intentionally non-linear. New evidence can move a venture backward, change the ICP, invalidate an offer, or park the venture.

## Unit of progress

Progress is not "more documents" or "more code".

Progress means one of:
- a critical assumption becomes better understood;
- evidence changes confidence in a claim;
- an expensive path is ruled out;
- a concrete customer behavior is observed;
- a gate decision becomes easier to justify;
- the next experiment becomes smaller and more decisive.

## Venture memory

The repository should preserve:
- hypotheses;
- evidence;
- decisions;
- experiments;
- learning;
- contradictions;
- revisit conditions.

This memory is more important than any single generated report.
